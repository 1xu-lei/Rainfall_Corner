> 2026 世界计算大会 · Central Park 开源智算青少年训练营

---

## 1. 作品一句话

《雨落街角》是一个**城市内涝防护的资源分配策略推演 Demo**：把固定 **5 点**建设资源分给 **5 个固定城市场景**，选择 **2 种降雨情境**之一，执行一次**确定性规则推演**，得到 **0–100 韧性评分**与一份可解释复盘（分项、联动、因果解释、优化建议）。

比赛比的是「规则可解释 + 视觉有辨识度 + 工程架构清晰」，不是水文学精度。

## 2. 功能边界

### 2.1 做什么

| 能力 | 说明 |
|---|---|
| 场景规划 | 学校 / 集市 / 公园 / 居民区 / 车站 五个场景**始终存在**，投入 0 点只表示「无专项投入」，不会隐藏 |
| 资源分配 | 总量固定 5 点，每场景 0–5 整数；总和**必须恰好为 5** 才允许推演，越界操作被拒绝并给出原因 |
| 降雨情境 | 持续型降雨（累计水量为主）与短时强降雨（峰值强度为主），共用同一套引擎，只换参数 |
| 城市水流关系 | 固定四条链路：学校→公园、集市→居民区、公园→车站、居民区→车站；车站为两路汇流的最终压力承受点，连线粗细取实际下泄量 |
| 确定性推演 | 6 步实时推演过程（入流 / 坡面汇流 / 上游调蓄 / 下游汇流 / 车站峰值 / 退水），动画只推进展示进度，不参与计算 |
| 结算复盘 | 总分、等级（S/A/B/C/D）、策略标签（专精 / 双核 / 偏科 / 均衡 / 多元）、五场景分项、四个简化风险指标、联动触发、事件日志、≥2 条因果解释、基于本轮数值的优化建议 |
| 历史与榜单 | 顶部导航的历史记录 / 排行榜 / 设置侧栏；历史优先读后端 SQLite，后端不可用时读浏览器快照（两条来源互不覆盖） |
| 三种界面版本 | A 雨夜指挥台（三栏 HUD）/ B 沉浸全景（城市全屏）/ C 水文仪（流域图 + 仪表），共用同一状态与引擎 |

### 2.2 不做什么（明确边界，避免误解）

- **不是**城市建设 / 自由建造游戏：没有自由摆放、没有建造队列。
- **不是**真实 GIS 或水动力学仿真：汇流是 0–1 相对负荷模型，风险指标是项目自定义的 0–100 简化指标，**不是工程单位**。
- **不引入随机性**：同一雨型 + 同一分配 + 同一规则版本 → 结果、事件、解释、`simulationId` 全部一致。
- 排行榜为**本机示例数据**（接口字段 `isDemoData = true`），不冒充联网榜单。

## 3. 规则模型（可阅读、可测试）

### 3.1 组合空间

五个场景投入 `x1..x5`，`xi ∈ {0..5}`，`Σxi = 5`，隔板法得

```
C(5+5-1, 5-1) = C(9,4) = 126
```

126 是数学组合数，策略差异来自「五条互不相同的场景收益曲线 + 雨型权重 + 3 条联动」。

### 3.2 投入档位（0–5 六档）

`无专项投入 / 初步介入 / 稳定发展 / 深度发展 / 阶段突破 / 极限专精`，每个场景的收益曲线**独立配置**，不是换名字共用一条曲线。

### 3.3 三条联动

| 联动 | 触发条件 | 效果 |
|---|---|---|
| 上游调蓄 | 公园 ≥ 3 | 下游汇流压力下降 |
| 排蓄协同 | 公园 ≥ 2 且 车站 ≥ 2 | 调蓄与排水形成协同收益 |
| 全域均衡 | 五场景均 ≥ 1 | 均衡发展奖励 |

### 3.4 评分

```
raw = Σ(场景权重 × 净安全度) + 联动奖励
展示分 = display_score(raw)   # 单调线性映射，只缩放不改排序
等级：S ≥ 85 / A ≥ 72 / B ≥ 58 / C ≥ 42 / D < 42
```

展示分映射区间与全部权重都写在 `rules/rules.json`，**改配置即改行为，引擎代码不动**。

### 3.5 反「固定最优解」红线

后端 `app/tests/test_sweep.py` 对 **126 组合 × 2 雨型 = 252 次**全枚举，断言：

- 得分恒在 0–100，不同分值数 > 60（实测 103 / 104）；
- **两种雨型的最优分配不相同**，且不存在任何一套分配同时拿下两者最优（`fixed_dominant = []`）。

实测分布：

| 雨型 | 最低 | 中位 | 最高 | 不同分值 | 最优分配 | 最高等级 |
|---|---|---|---|---|---|---|
| continuous 持续型 | 37.1 | 65.2 | 83.0 | 104 | `[1,1,3,0,0]` | A |
| burst 短时强降雨 | 54.0 | 81.0 | 100.0 | 103 | `[0,0,0,1,4]` | S |

## 4. 技术路线

### 4.1 分层

```
frontend/  Vue 3 + TypeScript + Vite + Tailwind + Pinia
  variants/        三个界面版本（A/B/C），只换信息架构与视觉组织
  views/           推演过程浮层、结算页
  components/      场景卡、分配器、水流图、联动图、结果仪表…
  stores/          唯一写入口（game / simulation / ui / scenario / allocation）
  engine/          ruleEngine.ts —— 与后端逐行对齐的前端引擎（252 组一致性校验）+ previewEngine.ts 入口
  services/        REST 客户端 + 数据源选择层 + 历史记录
backend/   FastAPI + Pydantic + SQLAlchemy（SQLite）
  api/             config / simulations / history / leaderboard
  schemas/         Pydantic 出参与校验
  services/        编排
  engine/          纯计算：scoring / simulation / flow / synergy / strategy / allocation
  config/          参数装载（全部阈值来自 rules/rules.json）
  repositories/    结果快照持久化
  tests/           pytest 32 项
rules/rules.json   规则唯一真源
```

### 4.2 关键约束

1. **引擎是纯函数**：`backend/app/engine/` 不 import FastAPI / SQLAlchemy，无随机数、不依赖时间与调用顺序。
2. **配置驱动**：场景曲线、雨型权重、联动阈值、评分映射区间、等级阈值全部集中在 `rules/rules.json`。
3. **单一写入口**：组件不直接改状态，只调 store action；组件不认识任何评分规则。
4. **诚实降级**：前端 1.8 s 超时即降级到本地预览引擎，并在界面明确标注「本地预览引擎」，绝不把预览结果伪装成后端结果。
5. **动画不参与计算**：推演过程只推进 `playbackStep`，「跳过 / 快速结算」与完整播放得到同一份数值。

### 4.3 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查（含 rulesVersion） |
| GET | `/api/config/scenarios` | 五场景 + 0–5 六档收益曲线 |
| GET | `/api/config/rain-types` | 两种雨型参数 |
| POST | `/api/simulations/run` | 推演；总和 ≠ 5 或越界返回 422 |
| GET | `/api/simulations/{id}` | 按 id 回查已保存结果 |
| GET | `/api/history?limit=20` | 最近推演（最新在前） |
| GET | `/api/leaderboard?limit=10` | 本地记录生成的示例榜单（`isDemoData=true`） |

## 5. 使用方式

### 5.1 三步上手

1. 双击根目录 **`start.bat`**（同时拉起后端 8000 与前端 5199，并打开浏览器）；
2. 左栏选一种降雨情境 → 右栏把 5 点分配完（如 学校 1 / 集市 1 / 公园 3 / 居民区 0 / 车站 0）；
3. 点 **开始推演** → 看 6 步推演 → 结算页看分数、分项、联动、解释与建议 → 「返回调整」或「再玩一次」。

详细启动与环境依赖见 `02_部署或运行入口/启动说明.md`。

### 5.2 界面说明

- **顶栏**：城市规划 / 历史记录 / 排行榜 / 设置；右上角显示当前数据源（后端引擎 / 本地预览引擎）与规则版本。
- **左栏**：降雨情境卡（切换雨型，雨滴粒子密度与强度实时变化）、`RAIN LOAD` 强度条、雨层开关、城市水流关系图。
- **中栏**：城市等距场景舞台，节点显示该场景当前投入与净安全度；浮层可开关雨幕。
- **右栏**：资源分配五行（缩略图 / 名称 / 方向 / 步进器 / 档位灯条）+ 已分配/剩余 + 均衡方案 / 清空 + 开始推演。
- **底栏**：预期效果预览（五场景环图 + 城市状态预测折线）。
- **版本切换**：左下角 `DESIGN REVIEW` 胶囊（或键盘 `1/2/3`）在 A/B/C 三个界面版本间切换，`?v=b` 可直接进入；三个版本共用同一套状态与引擎，结果完全一致。
- **结算页**：左侧五场景分项、中间总分与四项风险、联动与优化建议、右侧因果解释；底部为城市状态预测折线。

## 7. 已知限制

1. **规则为教学简化模型**：分数与风险指标不是真实工程单位，不能用于真实排涝决策。
2. **`burst` 雨型偏易**：中位分 81.0（A 级），演示张力弱于持续型；收紧只需改 `rules.json` 中 `rainTypes.burst.score_weights.station` 或 `defense_modifier.station`，改完必须重跑 `test_sweep.py`。
3. **满分饱和**：`display_score()` 在 100 处裁剪，`burst` 有 4 套分配并列 100.0；如需拉开，改 `scoring.raw_score_ceiling`（只改映射区间，不动排序）。
4. **历史与榜单是单机数据**：无账号体系，不做跨机同步。
5. **前端主包 765 kB**（gzip 260 kB）：ECharts / Naive UI 尚未按需拆分，属于后续优化项。
